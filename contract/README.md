# App ↔ server contract fixtures

Real payloads exchanged between the mobile app and the server, checked by tests
on **both** sides. See [docs/VERSIONING.md](../docs/VERSIONING.md) §6.

- `upload-summary/legacy-app-*.json`: what a released app version sends as the
  `summary` field of `POST /api/v1/activities`. **Frozen.** Never edit these;
  the server must accept them for as long as `MIN_APP_API_LEVEL` is 0.
- `upload-summary/api-level-N.json`: what the *current* app sends to a server
  at API level N. Golden files, generated by
  `mobile/test/core/api/upload_payload_test.dart` (run it with
  `--dart-define=UPDATE_CONTRACT=true` to rewrite them after a deliberate change).

`server/tests/test_api_contract.py` uploads every file here and requires a
`201`. For `api-level-N.json` at or below the server's own `API_LEVEL`, it also
requires that the server didn't silently ignore any field.

- `analysis-result/app-reads.json`: every `analysis.result` field an app reads,
  and its type. Only ever add entries. Checked against the real analyzer
  output by `server/tests/test_analysis_contract.py`.
- `gpx/<name>.gpx` + `<name>.expected.json`: GPX written by the app's real
  writer (golden files, `mobile/test/core/files/gpx_contract_test.dart`, same
  `UPDATE_CONTRACT` flag) and what the app means by it. The server's parser
  must extract exactly that (`server/tests/test_gpx_contract.py`).
